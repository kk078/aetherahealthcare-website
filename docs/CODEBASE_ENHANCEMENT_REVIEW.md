# Website enhancement review — September 7, 2026

The highest-value next investment is reliability and credibility: protect lead data, make delivery dependable, substantiate tool outputs, and enforce release checks before expanding the tool catalogue.

Scope: repository-wide inventory and static pattern checks across 327 source/data files, with focused inspection of shared infrastructure, lead flows, content generation, representative calculators/scrubbers, navigation, metadata, deployment and tests. There are 157 page files, including 92 under tools (the directory plus 91 individual tools), and 47 E2E test files. This is not an independent validation of every billing rule or a rendered accessibility/performance audit. Backend Worker/CRM implementations live outside this repository. No live lead submissions were sent.

Verification: `npm run typecheck` passed. `npm run build` passed after a network-enabled retry allowed Google Fonts to download; the first sandboxed attempt failed on font fetching. `npm run lint` reported 634 problems (118 errors, 516 warnings). E2E/browser tests were inspected but not executed. Only this report was added; application code was not changed.

**Immediate priorities**

1. **Move lead dispatch behind a controlled backend endpoint.** `src/lib/worker.ts:67–90,159–195,269–297` exposes notification topics, sends names/emails/phones/notes to ntfy without authentication, and saves the latest 50 submissions to localStorage without expiry. Third-party scripts on the same origin can access that storage. Remove the personal-data vault and send notifications containing only a lead reference through a protected backend. Inspect topic access settings before assuming confidentiality; this review did not read topic messages. ntfy documents that topics are public by default: https://docs.ntfy.sh/config/. Existing backend protections cannot be established from this repo.

2. **Make consent actually control tracking.** `src/components/ui/CookieConsent.tsx` only saves a preference; GoogleAds, RetargetingPixels, B2BVisitorTracker and the root-layout RB2B scripts do not read it. `src/app/layout.tsx:95–123` also includes two loading paths for the same RB2B script. Introduce shared consent state, defer optional trackers until accepted, support preference changes, and test network requests before/after consent. This is a confirmed behavior mismatch, not a jurisdiction-specific legal assessment.

3. **Remove the browser AI credential path.** `src/lib/aiAgent.ts:30,328–342` uses `NEXT_PUBLIC_AI_API_KEY` in a direct Gemini request. If configured, it is distributed to visitors. Route requests through the existing Worker with server-held credentials, request limits and input validation; rotate any credential previously shipped. Next.js confirms public variables are embedded in browser bundles: https://nextjs.org/docs/app/guides/environment-variables. No secret value was inspected.

4. **Fix lead delivery semantics and identity mapping.** `src/lib/worker.ts:94,161` parses `data.name || data.firstName ? ... : ...` such that a submission with only `name` produces an empty display name. `submitToWorker` returns only FormSubmit's result while CRM delivery runs independently; therefore a successfully stored CRM lead can still show failure. Conversely, HTTP 200 with a negative FormSubmit success body is accepted. Add typed payloads, provider response validation, timeouts, idempotency, and a durable acknowledgement. Test name-only leads, provider rejection, timeout, CRM success/email failure and duplicate retries.

5. **Distinguish demonstrations from verified operational data.** `PlatformTelemetryDashboard.tsx` labels hard-coded edge-node latencies, connection counts and SLA figures as live production telemetry. It also substitutes invented timing values when measurements are unavailable or zero. Show unavailable values honestly, label sample data, and connect real infrastructure metrics before claiming live monitoring. Reconcile zero-storage copy with actual lead storage and dispatch behavior. `DenialOverturnPredictor.tsx:192–209` calculates fixed heuristic scores but calls them statistical probabilities; show a readiness score unless there is a validated outcome dataset and calibration evidence.

**Reliability and release quality**

6. **Make CI a deployment prerequisite.** Lint currently reports **118 errors and 516 warnings**; TypeScript passes. `.github/workflows/ci.yml` does not run lint and selects only three page-test files plus two production API/header suites. `.github/workflows/deploy-cloudflare.yml` deploys independently of that workflow. Use one build artifact through lint/typecheck/build/test/deploy, expand coverage to representative tool families and mobile, and gate production on success. Add mocked form-delivery tests rather than enabling live submissions in CI.

7. **Publish generated articles through review.** `.github/workflows/auto-blog.yml` commits before building and deploys without the normal tests. `scripts/auto-blog.mjs:221` randomly assigns a named author. Create draft PRs with source references and a real accountable reviewer; ensure build-time configuration is identical across release paths. `src/lib/blogPosts.ts:4148` interpolates generated text directly into HTML consumed by `dangerouslySetInnerHTML`. Escape headings/list text and allowlist inline HTML tags, attributes and link protocols. This is an unsafe content path; no malicious published article was demonstrated.

8. **Bound file parsing work.** `src/app/free-assessment/FreeAssessmentClient.tsx:152` reads whole files without an upfront size limit and parses spreadsheets on the UI thread. Add file, row, sheet and PDF page limits, cancellation, a parsing worker, and clear malformed-file errors. Preserve the existing on-demand XLSX/PDF imports and local aggregation approach. Audit parser dependencies against current advisories before upgrading; this review did not run a dependency vulnerability audit.

**Discovery, performance and usability**

9. **Generate discovery metadata from one registry.** The manually maintained sitemap omits **83 tool pages** and campaign landing pages. Use a typed route/tool registry for sitemap entries, directory cards, search and metadata, with explicit indexing decisions for campaigns/demos. Preserve real modification dates instead of changing every non-blog date on each build. Add a build check that every intended indexable page is represented.

10. **Repair landing-page footer paths.** Five campaign pages link to `/privacy` and `/terms`; two also link to `/security`. Those paths have no matching page or in-repo redirect. Point them to `/compliance/privacy-policy`, `/compliance/terms-of-service`, and `/compliance/security`. External Cloudflare redirect rules were not inspected. Standardize canonical URLs, trailing slashes and title templates; several service titles already include the company name that the root title template appends again.

11. **Reduce JavaScript loaded by every visitor.** The root imports the command palette and callback/AI interface eagerly. Their import graph reaches the search index and payer/denial datasets: approximately 139 KB of search source, 471 KB of payer JSON and 443 KB of denial-reference JSON, before bundling/compression. Lazy-load search/chat internals on activation. The blog index imports full article content when summaries would suffice. Keep homepage/static article markup server-rendered and isolate interactions. Measure route-level transferred JavaScript and Core Web Vitals before claiming a speed improvement.

12. **Use accessible shared dialogs and forms.** FreePilotModal and ExitIntentCTA declare modal semantics without a complete focus trap/restoration implementation; ExitIntentCTA lacks Escape handling. Reuse the already-installed Radix Dialog primitive. Associate labels with input IDs, connect errors with `aria-describedby`/`aria-invalid`, announce submit status, and implement tab keyboard semantics. Test keyboard-only use and mobile layouts. `FadeIn.tsx` emits opacity zero until JavaScript runs; make content visible by default and progressively enhance animation.

13. **Simplify the conversion journey and measure actual outcomes.** Coordinate callback/chat, exit-intent, pilot and cookie surfaces so they cannot compete during a form or tool session. Use one primary action per page. Make required phone/specialty fields proportional to the inquiry and specify the timezone for consultation slots. `BookingEmbed.tsx:71` tracks a calendar-link click as `schedule_appointment`; distinguish calendar-open, booking-confirmed and qualified-lead events, with confirmation driven by a trusted booking callback. Validate campaign attribution reaches CRM records, not only email fallbacks.

**Maintainability and content quality**

14. **Separate billing rules from visual components.** Many specialty scrubbers combine large rule blocks, calculations, explanatory text and repeated controls. Extract pure evaluators, typed inputs/results and shared tool shells without forcing unrelated specialty logic into one abstraction. Attach source URL, effective date, payer/plan scope and review date to each rule. Prioritize boundary/negative tests: invalid or missing inputs, modifier interactions, date boundaries and mutually exclusive selections. No conclusion here establishes that individual clinical/coding rules are correct.

15. **Consolidate claims, metadata and design tokens.** Centralize contact details, pricing assumptions, verified outcome claims and source-backed benchmarks. Replace broad dark-mode CSS overrides with semantic surface/text tokens as components are touched. Add real reviewer profiles and methodology to case studies and benchmark tools. Keep `docs/FUNCTIONALITY_AUDIT.md` as a dated historical audit; its blanket remediation statement does not describe this checkout's current findings.

**Suggested sequence:** First address lead privacy, consent, credentials and delivery. Next make CI authoritative, label unsupported telemetry, repair links/sitemap and sanitize publishing. Then improve shared dialogs, load performance, conversion measurement and tool architecture. Accept changes using observable outcomes: no optional requests before consent, one acknowledged lead per submission, passing release checks, complete intended sitemap coverage, keyboard-operable dialogs and source-versioned calculator outputs.
